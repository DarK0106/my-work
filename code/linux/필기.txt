Shell, 쉘
- 여러종류의 쉘이 있다.

- Bourne Shell(sh)
    - 유닉스에 최초로 사용된 표준 쉘
    - sh 명령어
    - 단순하고 가볍다. 기능이 적다.

- Bash(Bourne Again Shell)
    - 리눅스에서 가장 많이 사용하는 기본 쉘

- zsh(Z Shell)
    - bash 모든 기능 + 자동 완성, 테마, 플러그인 등 제공
    - macOS





리눅스 파일 시스템 > 구조

- /home: 사용자(계정) 폴더
- /etc: 시스템 설정. 잘못 건드리면 시스템 불안정
- /usr: Unix System Resources. 애플리케이션나 라이브러리 등을 관리
        - 톰캣, JDK > 사용자가 직접 설치하는 경우
- /opt: Optional. 애플리케이션나 라이브러리 등을 관리
        - 대형 소프트웨어 or 상용 소프트웨어
- /root: 관리자(root) 계정의 홈 디렉토리
- /var: Variable. 가변 데이터
        - 로그, 이메일, 임시 파일 등.. 자주 변경되는 데이터
- /mnt: Mount. 리눅스가 외부 저장소를 연결해놓은 디렉터리

2. ls, List
- $ ls [옵션] [경로]

- 디렉토리의 파일/폴더 목록을 출력

- $ ls -l: 상세 정보까지 출력(long)
- $ ls -a: 숨긴 파일/폴더까지 출력(all)
- $ ls -al
- $ ls -la

- 출력 결과 의미
    a. l rwx rwx rwx > 777
       d rwx rwx rwx
       - rwx rwx rwx

       첫번째 문자: 파일 유형
        - '-': 일반 파일
        - 'd': 디렉터리
        - 'l': 심볼릭 링크

       2~4번째 문자: 소유자(User) 권한
       5~7번째 문자: 그룹(Group) 권한
       8~10번째 문자: 기타 사용자(Other) 권한

    b. 소유자(Owner): 파일/디렉토리 소유. 파일/디렉토리를 직접 만들었거나, 소유권을 가지고 있는 유저
    c. 그룹(Group): 계정의 집합


    d rwx r-x r-x aaa
    - rw- r-- r-- 테스트.txt

    권한(Permission)
    - 파일/디렉터리에 대해 누가 + 어떤 작업이 가능한지에 대한 정책
    - 루트(root) 사용자가 변경한다.
    - 읽기(r, 4): 파일(내용 읽기), 폴더(내용 열람)
    - 쓰기(w, 2): 파일(내용 수정), 폴더(새파일 생성/삭제)
    - 실행(x, 1): 파일(실행), 폴더(접근)
    - rw- > 읽기+쓰기 > 4 + 2 > 6
    - rwx > 읽기+쓰기+실행 > 4 + 2 + 1> 7
    - r-x > 읽기+실행 > 4 + 1 > 5
    - 2^0 = 1 1
    - 2^1 = 2 0
    - 2^2 = 4 0
    - 2^3 = 8 1

7. rm, Romove
- $ rm [옵션] [파일]
- $ rm -r [디렉터리]
- $ rmdir [디렉터리]

- 파일 삭제: 현재 디렉터리에 쓰기(w) 권한이 필요
- 폴더 삭제: 빈폴더만 삭제 가능

$ rm aaa.txt
$ rm aaa
$ rmdir aaa


파일 삭제
$ rm aaa.txt        # 파일 삭제
$ rm -f aaa.txt     # -f. Force

폴더 삭제
$ rmdir aaa         # 빈폴더 삭제
$ rm -r aaa         # 내용없는 폴더 삭제
$ rm -r aaa         # 내용있는 폴더 삭제
$ rm -R aaa         # 내용있는 폴더 삭제
$ rm -rf aaa        # 내용있는 폴더 강제 삭제

10. vi, visual editor
- 텍스트 편집기

- vi 모드
    - 명령 모드: 명령 단축키를 입력하면 그 기능을 실행
    - 입력 모드: 텍스트 편집, 명령 모드인 상태에서 i 누르면 됨
    esc 누르면 다시 명령 모드
    - 명령 행 모드: 명령 모드인 상태에서 : 누르면 됨
    추가 명령을 하기 위한 일종의 서브 창

명령 모드 단축키
- dd: 현재 라인 삭제
- u: 명령 취소
- D: 커서 위치로부터 행의 끝까지 삭제
- yy: 줄 복사
- p: 붙여넣기

명령 행 모드 커맨드
- :q -> 프로그램 종료(quit)
- :w -> 기존 파일을 열었을 때, 저장(write)
- :w aaa.txt -> 새 파일을 생성했을 때, 저장(write)
- :wq -> 저장하고 종료

15.1. apt-get update

이 레포지토리들을 최신 버전으로 갱신

- sudo apt-get install net-tools(apt-get: 구형)
또는
- sudo apt install net-tools(apt: 신형)

15.3 apt-get remove
- 프로그램 삭제
- sudo apt-get remove 패키지이름

15.4 apt-get purge
- purge가 되게 강력한 의미라 조심해서 써야 함
- remove는 패키지(프로그램)만 삭제함, 그래서 설정 파일을 그대로 남김
- 그래서 remove로 지웠다가 다시 패키지를 깔면 이전에 설정했던 옵션이 남아있음
- purge는 아주 깔끔하게 다 지워버림

15.5 apt-get autoremove
sudo apt-get autoremove
- 더 이상 사용하지 않는 패키지를 삭제한다
- 의존성을 체크해서 더 이상 참조되지 않는 패키지를 삭제함

15.6 apt-get clean
sudo apt-get clean
- 15.5에서 했던 동작 + 설치 파일 까지 지워버림
- autoremove보다 더 강력한 녀석

그래서 VMware 나 VirtualBox를 사용해서 가상머신을 만들어

컨테이너는 실행할때 두 가지 모드 중 선택해야함
    1. Attach Mode, 다른 말로 Foreground Mode
        - 컨테이너와 쉘(터미널)이 서로 연결되어있는 상태
        - 컨테이너 실행 중에는 해당 쉘(터미널)에서는 다른 작업이 불가능하다
    2. Detached Mode, 다른 말로 Background Mode
        - 컨테이너와 쉘(터미널)이 분리된 상태로 실행
        - 컨테이너가 실행 중이더라도 해당 쉘(터미널)로는 다른 작업이 가능하다

docker image pull httpd
docker create --name apache httpd

docker start apache <- 기본으로 Detached Node, 즉 백그라운드 모드로 실행됨
docker start -a apache <- 포그라운드 모드로 실행, 이 컨테이너가 이 터미널을 붙잡고 있어서
이 컨테이너가 끝나기 전에는 다른 작업을 못함. ajax로 치면 동기 통신과 비슷
이 터미널 창을 닫아버리면 컨테이너도 같이 중단됨
그럼 터미널창 어떻게 씀? <- 하나 더 띄워야 함
종료하려면 Ctrl + C

Detached Mode로 실행하면 실행하고 나서 창 닫아버려도 됨
<- 실시간으로 무슨 일이 일어나는지 확인할 수 없음

결론:
Attach Mode 는 개발할 때 많이 사용
Detached Mode 는 실제로 운영 중일 때 사용

운영중일때 Attach Mode 는 불편해서 안 씀

공인 IP vs 사설 IP
공인 IP는 전세계에 유일하다. 나만 가질 수 있음, 그래서 1년마다 돈내야함
그 공인 IP는 내 공유기에 할당되어있어야함 그래야 전세계 수많은 공유기 중에
내가 쓰는 공유기를 찾을 수 있으니까(내가 우리 집 와이파이로 카톡할때 상대방이
카톡을 보낼 때 IP를 알아야 제대로 보낼 수 있음)
그럼 컴퓨터 TV 스마트폰 다 공인 IP 쓰면 안 됨? <- 돈이 드니까 그렇게 안함
그래서 사설 IP를 씀 
사설 IP는 [컴퓨터 TV 스마트폰(내부 네트워크)]끼리 구별할 수 있는 IP이다.
내부 네트워크 바깥에서는 이 사설 IP가 뭔지 모름
공유기가 내부 네트워크에 있는 기기들 하나씩 사설 IP를 지정해줌, 그걸로 구별함

그래서 상대방이 나한테 카톡을 보낼때 공인 IP만 써서 보내는게 아니고 포트번호까지
같이 써서 보냄, 그래야 카톡을 무슨 기기로 보낼지 알 수 있으니까

예: 외부에서 80이라는 포트번호로 들어오면 
내부에서 8123이라는 번호를 쓰는 기기(예: 내가 쓰는 스마트폰)로 포워딩을 시켜라

스토리지 마운트(중요)
- 문제: 기존의 cp 명령어는 컨테이너가 삭제되면 그 안에 있던 파일도 같이 삭제된다
결국 컨테이너 안의 파이릉르 보존하려면 호스트에 복사를 해야 한다 <- 귀찮음

이걸 해결하기 위해 스토리 마운트라는걸 만들었음

스토리지 마운트는 컨테이너(가상 컴퓨터)에 외장 하드처럼 연결한다고 보면됨
스토리지 마운트의 목적은 컨테이너가 삭제되더라도 데이터를 유지하기 위해

컨테이너를 생성할때 스토리지 마운트를 지정하면 된다
    - 단 컨테이너를 생성한 이후에는 스토리지 마운트를 할 수 없다.

컴퓨터로 치면 컴퓨터 조립도 전에 외장하드 먼저 꽂는 것

스토리지 마운트를 하면 컨테이너의 경로의 디렉토리의 모든 상태가 덮어쓰기 된다.
(기존 파일을 모두 지워버림)

스토리지 마운트의 방식은 2가지

1. 바인드 마운트, Bind Mount <- 개발/테스트 할 때 쓰는 용도
    호스트 시스템의 특정 디렉터리를 컨테이너에 마운트한다.
    실습: C:\Ssangyong\code\drive 디렉터리를 새로 만들었음

2. 볼륨 마운트, Volume Mount <- 많이 씀(운용할 때)
    - 도커 엔진이 직접 관리하는 저장 공간을 볼륨이라고 한다
    - 도커가 관리하는 외장 하드
    - 볼륨을 특정 컨테이너에 결합(마운트)헤서 사용이 가능하다

바인드 마운트:
docker run -v 호스트경로:컨테이너경로

로컬 경로는 C:\Ssangyong\code\drive

컨테이너 생성하기

<- home이라는 폴더에 마운트하겠습니다

상황: 아파치 컨테이너 + 로컬 개발 + 바인드 마운트

보통 마운트할 폴더랑 컨테이너랑 1:1로 만듦

로컬 폴더: C:\Ssangyong\code\drive2

예시 상황: 뭔가 문제가 생겨서 apache 라는 이름의 컨테이너를 지워야함

우리가 만든 이미지를 활용해 컨테이너에서 쓰는것

이미지를 생성하기
- 기존 컨테이너를 이미지로 변환하기
- Dockerfile 스크립트로 이미지를 생성하기(보편적)

Dockerfile 만들기
이름 그대로 Dockerfile 만들면 됨, 그냥 텍스트 파일

FROM httpd # 베이스 이미지
COPY ./dir /usr/local/apache2/htdocs/ # 세팅
EXPOSE 8080

Dockerfile
- 이미지를 빌드(생성)하는 텍스트 기반 스크립트
- 베이스 이미지 + 파일 복사 + 시작 명령어

docker build -t 이미지이름 .
docker build -t myapache .
docker build -t myapache:latest .
docker build -t myapache:1.1 .

docker run -d --name apache -p 8080:80 myapache

이미지 빌드하기
docker build -t board .
docker build -t board-bash .

컨테이너 실행하기
docker run -it --name board board
docker run -it --name board-custom board-custom
docker run -it --name board-custom board-bash

컨테이너는 그 안에 동작되는 프로그램이 종료되면 자동으로 컨테이너도 종료된다

1. 로컬(사설) 도커 레지스트리 운영하기

# 사설 레지스트리 생성하기
docker run -d --name registry -p 9999:5000 registry

# 배포할 이미지 생성
docker build -t localhost:9999/board .

# 사설 레포지토리에 이미지를 업로드하기
docker push localhost:9999/board

# 사설 레포지토리에 내가 업로드한 이미지를 확인하기
생략되었지만 GET 요청으로 확인함
curl http://localhost:9999/v2/_catalog

# 사설 레포지토리로부터 이미지를 다운로드 + 컨테이너
docker image pull board                <- 도커 허브로부터 다운로드 
docker image pull localhost:9999/board <- 사설 레포지로부터 다운로드

도커 허브를 쓰는 방법, public으로 사용(보통 private)
1. 도커 허브에 로그인

2. 업로드할 이미지 + 태그 추가
docker build -t 도커허브ID/이미지이름:태그이름 .
docker build -t pinnpublic/board:v0.0.1 .

도커 허브에 올리기
docker push pinnpublic/board:v0.0.1

다른 사용자가 이미지 + 컨테이너 를 다운받는 상황
docker run -it --name board pinnpublic/board:v0.0.1
