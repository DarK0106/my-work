톰캣은 JSP 페이지를 어떻게 처리할까?
위에서 한줄씩 내려가면서 실행하지만 절대 규칙이 있다
	- 내(톰캣)가 이해하는 구문은 실행한다
	- 내(톰캣)가 이해하지 못하는 구문은 넘어간다
	- 자바는 톰캣이 이해할 수 있음
	<%@ page language="java" contentType="text/html; charset=UTF-8"

    - 톰캣은 HTML이 뭔지 모른다
    - 톰캣이 미리 준비해둔 공간에 엔터를 그냥 붙여넣기만 한다?

page 지시자
- webapp -> "ex03.jsp"
- JSP 페이지 실행과 관련된 여러가지 정보를 톰캣에게 알려주는 역할
- 보편적으로 항상 JSP 페이지 첫줄에 작성한다
- page 지시자는 여러개 작성이 가능하다

<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
    
    a. language="java"
    	- JSP 페이지에서 사용할 프로그래밍 언어 지정
    	
    b. contentType="text/html; charset=UTF-8"
    	- 동적으로 생성된 페이지의 설정
    	- text/html
    	- charset=UTF-8: 돌려줄 HTML 페이지의 인코딩
    	<- 브라우저한테 알려주는 정보들
    
    c. pageEncoding="UTF-8"
    	- 현재 JSP 페이지의 설정

내장 객체의 생명 주기
- pageContext, request(*중요), session(*중요), application
- 데이터 저장 기능 때문에 생명 주기를 알아두는게 중요하다

- pageContext: 생성(페이지 요청) ~ 소멸(페이지 반환) 
	<- 4개의 객체 중 생명 주기가 가장 짧다
	
- request: 생성(페이지 요청) ~ 소멸(페이지 반환)
		   생성(페이지 요청) ~ 페이지 이동(forward) ~ 소멸(다음 페이지 반환)
		   
- session: 생성(사용자가 사이트에 처음 방문했을 때) ~ 소멸(사용자가 사이트에서 나갈 때)

- application: 생성(사이트에 첫 번째 사용자가 방문했을 때) ~ 소멸(사이트에 마지막 사용자가 나갈 때)
	<- 첫번째 사람이 만든걸 다같이씀, 크롬으로 들어간 다음 엣지로 들어가면 application만 카운트가 올라감

session(가장 중요!!) & application
	- session: 데이터 저장 용도 <- 개인정보 저장할 때 사용(개인 사물함)
	- application: 데이터 저장 용도 <- 공용 정보 저장용(공용 사물함)
	- "ex13_session.jsp"
	- "ex13_session_2.jsp"
	- "ex14_session.jsp"
