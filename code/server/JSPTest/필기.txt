JSP, Java Server Pages
- 자바를 이용해서 서버측에서 웹 페이지를 만드는 기술
- JSP는 서블릿입니다.(*중요)
- JSP는 톰캣이 HTML과 동일하기 취급한다. -> 브라우저가 직접 호출 가능

Servlet/JSP Container -> 톰캣

- src -> main -> webapp -> "ex01.jsp"

JSP 구성 요소

1. JSP 지시자, JSP Directive
	- <%@ %>
	- JSP Container(톰캣)에게 페이지 처리를 위한 여러가지 상황을 전달
	a. page 지시자
	b. include 지시자
	c. taglib 지시자

2. 스크립트 요소, Scripting Elements
	- <% %>
	- 자바 코드와 관련된 기능들
	a. 스크립틀릿, Scriptlet
	b. 익스프레션, Expression
	c. 선언부, Declaration
3. 액션 태그, Action Tags
	- <jsp:태그명>, <c:태그명> 등 ..
	- 프로그래밍 기능이 있는 태그

4. 내장 객체, Built-in Objects
	- 톰캣이 알아서 생성 후 개발자에게 제공하는 객체
	
톰캣은 JSP 페이지를 어떻게 처리할까?
위에서 한줄씩 내려가면서 실행하지만 절대 규칙이 있다
	- 내(톰캣)가 이해하는 구문은 실행한다
	- 내(톰캣)가 이해하지 못하는 구문은 넘어간다
	- 자바는 톰캣이 이해할 수 있음
	<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
    - 이건 일종의 환경설정임
    - 엔터 도 소스의 일부분이다(이것도 HTML 코드)
    - 톰캣은 HTML이 뭔지 모른다
    - 톰캣이 미리 준비해둔 공간에 엔터를 그냥 붙여넣기만 한다?

브라우저 - 톰캣 - [소스(JSP CSS Java HTML 이 뒤섞여있음)]
브라우저가 소스 달라고 요청함
톰캣이 무조건 주진 않음
톰캣은 자바 언어를 실행하는 주체
브라우저는 HTML CSS JavaScript를 실행하는 주체

문제: 서로 다른 언어들이 한 파일에 들어있음
그래서 서로 약속함
브라우저(클라이언트)가 톰캣한테 소스 달라고 요청했는데 톰캣이 그냥 그대로 갖다주면
브라우저가 해석을 해야하는데 문제는 브라우저가 JSP랑 자바가 뭔지 모름

그래서 톰캣이 자기가 할 수 있는 JSP랑 자바는 미리 실행을 해버림
실행을 해버리면 자바랑 JSP가 사라져버림

그렇게 된 페이지를 톰캣이 브라우저한테 주는것

결론: 서버에서는 자바를 처리하고 브라우저인 클라이언트에서는 클라이언트 코드가 실행됨
 
서버측에서 먼저 처리가 끝난 결과를 브라우저가 가져다가 실행하는것

page 지시자
- webapp -> "ex03.jsp"
- JSP 페이지 실행과 관련된 여러가지 정보를 톰캣에게 알려주는 역할
- 보편적으로 항상 JSP 페이지 첫줄에 작성한다
- page 지시자는 여러개 작성이 가능하다

<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
    
    a. language="java"
    	- JSP 페이지에서 사용할 프로그래밍 언어 지정
    	
    b. contentType="text/html; charset=UTF-8"
    	- 동적으로 생성된 페이지의 설정
    	- text/html
    	- charset=UTF-8: 돌려줄 HTML 페이지의 인코딩
    	<- 브라우저한테 알려주는 정보들
    
    c. pageEncoding="UTF-8"
    	- 현재 JSP 페이지의 설정
