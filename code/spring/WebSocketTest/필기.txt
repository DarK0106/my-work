웹 소켓, WebSocket
- 소켓(Socket) -> 네트워크상 호스트간의 데이터를 주고받는 규약(인터페이스_
- WebSocket -> ws 프로토콜을 기반으로 웹 클라이언트(js)와 서버 사이에 통신을 제공하는 기술

개념 비교
1. 이전 환경
    - 웹서버 <- (데이터) -> 브라우저
    - 비연결 지향
    - 클라이언트의 의지만으로 서로 연결이 가능
    - 굳이 따지자면 편지와 유사함
    
2. 이전 환경(ajax)
    - 웹서버 <- (데이터) -> XMLHttpRequest 객체
    - 비연결 지향
    - 클라이언트의 의지만으로 서로 연결이 가능
    - 굳이 따지자면 편지와 유사함
    
3. 소켓 환경(ws)
    - 웹 소켓 <- (데이터) -> 웹 소켓
    - 연결 지향
    - 전화기와 유사함
    ex) 카톡
    
소켓 동작
1. 호스트A, 호스트B

2. 호스트A -> 소켓(전화기) 생성 + IP주소(+포트번호)
*IP주소(+포트번호) 이걸 종단점이라고 한다*
3. 호스트B -> 소켓(전화기) 생성 + IP주소(+포트번호)

A가 B한테 전화를 걸려면 B의 전화번호(IP주소(+포트번호))가 있어야함
서로 전화번호를 알려줘야 하는게 아니고, 이미 서로의 전화번호를 알고 있는 상태에서 전화하는 것

4. 호스트B가 전화를 받는 사람, 즉 서버 역할이다. 미리 수신 대기 준비를 한다(Listener)
5. 호스트A는 전화를 거는 사람, 즉 클라이언트 역할이다. 호스트B의 종단점과 연결을 시도한다.
6. 호스트B가 호스트A의 연결을 수락했다.
7. 호스트A와 호스트B가 서로 연결되었다. 서로간의 데이터를 송수신한다.
8. 호스트A, 호스트B가 연결을 종료한다.

A가 B의 리스너와 연결되면 B쪽에서 새로운 연결점? 을 바로 만들어서 
A와 B의 전화를 하기 위한 연결? 이 새로 생긴다
